# راهنمای کاربر — تحلیلگر هوشمند صوتی

## این ایجنت چه کاری انجام می‌دهد؟

تحلیلگر هوشمند صوتی برای کاربر فارسی‌زبان ساخته شده تا یک فایل صوتی را بفهمد، متن آن را استخراج کند و درباره محتوای آن پاسخ یا خلاصه تولید کند.

### قابلیت‌ها

| قابلیت | توضیح ساده |
|---|---|
| تبدیل گفتار به متن | صدای فایل را به متن زمان‌بندی‌شده تبدیل می‌کند. |
| تشخیص زبان | زبان اصلی گفتار را تشخیص می‌دهد. |
| تفکیک گویندگان | مشخص می‌کند هر بخش از صدا مربوط به کدام گوینده است. |
| تحلیل گویندگان | روی زمان‌بندی گفتار و گویندگان تحلیل ترکیبی انجام می‌دهد. |
| جست‌وجو در متن صوت | کلمه یا عبارت را پیدا می‌کند و زمان آن را نشان می‌دهد. |
| موضوعات و فصل‌ها | موضوعات اصلی و بخش‌های زمانی فایل را استخراج می‌کند. |
| خلاصه‌سازی | متن استخراج‌شده را به یک خلاصه کوتاه و خوانا تبدیل می‌کند. |
| افراد و موجودیت‌ها | نام افراد، مکان‌ها و موارد مهم را از متن استخراج می‌کند. |
| رویدادهای صوتی | رخدادهای غیرگفتاری صوت را تحلیل می‌کند؛ Provider این بخش هنوز در حال تکمیل است. |
| شواهد زمانی | بخش‌های دقیق صوت که از پاسخ پشتیبانی می‌کنند را برمی‌گرداند. |
| پرسش و پاسخ مستند | فقط بر اساس شواهد استخراج‌شده از صوت پاسخ می‌دهد. |

## برای اولین تست خلاصه‌سازی چه چیزی لازم است؟

برای مسیر «فایل صوتی → خلاصه متنی» فقط دو بخش لازم است:

1. **تبدیل گفتار به متن:** WhisperX محلی یا یک سرویس ASR ریموت.
2. **مدل زبانی:** یک مدل زبانی محلی یا ریموت برای خلاصه‌سازی.

Whisper/WhisperX خودش خلاصه‌ساز نیست؛ وظیفه آن تولید متن است.

## نمایش نتیجه در پنل

برای عملیات «تحلیل کن» و «پرسش و پاسخ»، پاسخ نهایی در همان پنل مرکزی چت نمایش داده می‌شود. شواهد زمانی و citationها بخشی از داده داخلی پاسخ هستند و برای جلوگیری از شلوغی پنل به‌صورت chunkهای جداگانه در مرکز گفتگو نمایش داده نمی‌شوند.

برای عملیات `ask`، `evidence` و `analyze` یک فایل Markdown خوانا نیز در بخش خروجی‌های قابل دانلود قرار می‌گیرد.

## تنظیمات عمومی

### نوع محتوای صوتی

نوع فایل را مشخص می‌کند تا تنظیمات پیش‌فرض معنایی مناسب‌تر باشند:

- عمومی
- پادکست
- جلسه
- سخنرانی / کلاس
- مصاحبه
- تماس / مکالمه

برای تست اولیه می‌توانید «عمومی» را نگه دارید.

## تنظیمات تبدیل گفتار به متن

### روش تبدیل گفتار به متن

مشخص می‌کند متن از کجا تولید شود:

- **WhisperX محلی:** مدل روی همین کامپیوتر اجرا می‌شود.
- **سرویس ریموت:** یک API صوتی از راه شبکه استفاده می‌شود.
- **ابتدا WhisperX، سپس ریموت:** اولویت با محلی است؛ اگر Provider محلی تنظیم نشده باشد، ریموت انتخاب می‌شود.
- **ابتدا ریموت، سپس WhisperX:** اولویت با ریموت است؛ اگر Provider ریموت تنظیم نشده باشد، محلی انتخاب می‌شود.

### مسیر مدل WhisperX

مسیر پوشه یا مدل WhisperX روی همین کامپیوتر است. برای اجرای کاملاً محلی، **همین مسیر به‌تنهایی برای مشخص‌کردن مدل کافی است**.

مثلاً:

`C:\Users\coole\Desktop\Python_projects\LLM\models\...`

### نام مدل Whisper (اختیاری)

وقتی مسیر مدل را وارد کرده‌اید، این گزینه را خالی بگذارید. فقط زمانی لازم است که بخواهید به‌جای مسیر محلی از شناسه/نام مدل استفاده شود.

### دستگاه پردازش Whisper

- **CUDA:** استفاده از کارت گرافیک.
- **CPU:** استفاده از پردازنده.

با توجه به محیط فعلی Cheshm، برای اجرای GPU گزینه CUDA مناسب است.

### نوع محاسبه Whisper

نوع عددی محاسبات مدل است. برای GPU معمولاً `float16` انتخاب مناسبی است؛ در CPU بسته به مدل می‌توان از `int8` یا `float32` استفاده کرد.

### اندازه دسته Whisper

تعداد بخش‌هایی است که Whisper هم‌زمان پردازش می‌کند. مقدار بیشتر می‌تواند سرعت را افزایش دهد ولی حافظه GPU بیشتری لازم دارد.

برای شروع مقدار 8 مناسب است؛ اگر حافظه GPU کم آمد آن را کاهش دهید.

## تنظیمات ASR ریموت

این قسمت فقط زمانی لازم است که «سرویس ریموت» را انتخاب کنید.

| تنظیم | معنی |
|---|---|
| Base URL | نشانی پایه سرویس API، مثلاً `https://provider.example/v1` |
| API Key | کلید احراز هویت سرویس |
| Model | نام مدلی که همان سرویس برای تبدیل گفتار به متن ارائه می‌دهد |

**API Key و Model دو چیز جدا هستند.** API Key فقط اجازه دسترسی می‌دهد و Model مشخص می‌کند کدام مدل اجرا شود.

## تنظیمات مدل زبانی

این بخش برای خلاصه‌سازی، موضوعات، موجودیت‌ها و پرسش‌وپاسخ استفاده می‌شود.

### مدل زبانی محلی

- **Local Base URL:** نشانی سرویس OpenAI-compatible محلی.
- **Local Model:** نام مدل فعال روی همان سرویس.

### مدل زبانی ریموت

- **Base URL:** نشانی سرویس OpenAI-compatible.
- **API Key:** کلید دسترسی.
- **Model:** نام مدل زبانی مورد استفاده.

این سه مقدار با هم Provider ریموت را کامل می‌کنند.

### کلید Hugging Face چیست؟

این کلید برای احراز هویت هنگام دریافت/استفاده از مدل تفکیک گویندگان از Hugging Face است؛ **کلید مدل Whisper معمولی نیست** و فقط برای بخش تشخیص گویندگان لازم می‌شود. citeturn913407search6

### مدل تفکیک گویندگان

مدل pyannote مورد استفاده برای تعیین اینکه چه کسی در چه بازه‌ای صحبت کرده است. مقدار فعلی پیش‌فرض `pyannote/speaker-diarization-community-1` است.

## تعداد شواهد در پاسخ

حداکثر تعداد قطعه‌های زمانی است که در پاسخ‌های مستند برگردانده می‌شود. برای شروع مقدار 20 مناسب است.

## ساده‌ترین تست واقعی

1. در تنظیمات، WhisperX محلی را انتخاب کنید.
2. مسیر واقعی مدل WhisperX را وارد کنید.
3. دستگاه را CUDA بگذارید.
4. نوع محاسبه را `float16` بگذارید.
5. اندازه دسته را 8 بگذارید.
6. در بخش مدل زبانی، یک Provider محلی یا ریموت را کامل تنظیم کنید؛ در حالت ریموت حتماً Base URL، API Key و Model را هر سه وارد کنید.
7. فایل صوتی را در پنل بارگذاری کنید.
8. در چت بنویسید: «خلاصه کن».
9. نتیجه در چت نمایش داده می‌شود و فایل `audio_summary_<execution_id>.txt` در بخش خروجی‌های قابل دانلود قرار می‌گیرد.

برای اولین تست نیازی به فعال‌کردن تفکیک گویندگان، رویدادهای صوتی یا پرسش‌وپاسخ ندارید.
